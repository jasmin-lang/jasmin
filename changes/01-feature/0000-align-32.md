- New ARM option `-align-32`: the printer gives every instruction an explicit
  width (`.n` or `.w`), aligns every function on 4 bytes, and widens one
  16-bit instruction in each odd-length run of them, so that every 32-bit
  instruction starts at a 4-byte aligned address.
  Where a run has no instruction that can be widened (only `it`, `bx` or
  `muls`), the 32-bit instruction that follows stays misaligned, since a
  padding `nop` would cost more cycles than it saves.
  On cores that fetch instructions 32 bits at a time from flash, such as the
  Cortex-M3, a 32-bit instruction at an address `4k+2` costs extra fetch
  cycles.
  Without the option, the assembler picks a 16-bit encoding wherever it can
  and each one shifts the alignment of all the code that follows it, which
  cost 10 % on straight-line Keccak code on a Cortex-M3
  ([PR #xxxx](https://github.com/jasmin-lang/jasmin/pull/xxxx)).
